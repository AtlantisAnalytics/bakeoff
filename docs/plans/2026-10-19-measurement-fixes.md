# Measurement Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bundles record the harness commit and the KV cache's capacity, week.json reports cross-host
quality agreement and KV fit, and the method text says how quality, memory and KV should be read.

**Architecture:**
- **Commit:** `export-subst` writes the commit into `src/bakeoff/_commit`, and `env.py` falls back to it.
- **KV:** a new client call parses vLLM's `cache_config_info`, and the fit pass derives a `kv_fraction`
  per step from it.
- **week.json:** `week.py` gains optional fields, which `week.v1.json` gets as additive properties. The site
  renders one agreement line, and the method page gains a "Measurement notes" section.

**Tech Stack:** Python 3.11+ with httpx only, pytest and ruff via uv. The site is plain HTML generated by
`bakeoff site`.

**Spec:** `docs/specs/2026-10-19-measurement-fixes-design.md`

## Global Constraints

- **Additive only:** `bundle_format` stays `"m1"`. `week.v1.json` gains only optional properties, and
  `required` lists are unchanged.
- **Verdicts and eligibility are unchanged:** no edits to `verdicts.py` or `runview.ineligible_reasons`.
- **Provenance:** new bundle fields use `bakeoff.env.field(value, source)` with source `reported`,
  `derived` or `measured`; `field(None, …)` gives `not_captured`.
- **Old bundles stay identical through rederive:** the new week.json run-fit keys are emitted only when the
  bundle has `fit.kv`. `quality_agreement` is omitted when it would be empty. (No week is published on
  `main` yet, but keep this property.)
- **Scrub:** no hostnames, IPs, ports or usernames in code, tests, fixtures or docs. Describe hardware by
  envelope, e.g. "1× RTX 3060 12 GB".
- **Generated site:** after any change to `site_src/` or `web/`, run `uv run bakeoff site` and commit
  `site/`. CI runs `bakeoff site --check`.
- **Every task ends green:** `uv run ruff check`, `uv run ruff format --check` and `uv run pytest -q`.

## Review Focus

1. **A `cache_config_info` label value containing an escaped quote or comma,** for example
   `prefix="a\"b,c"`. The parse must still find `num_gpu_blocks` and `block_size`. → Task 2 test
   `test_cache_config_escaped_labels`.
2. **`num_gpu_blocks` of `"None"` or `"0"`** (vLLM prints `None` before profiling finishes). The capacity
   must be `not_captured`, not 0, and nothing may divide by zero. → Task 2 test
   `test_kv_summary_unusable_blocks`.
3. **A fit pass aborted mid-way.** The partial summary must still carry a `kv` object (`not_captured`), so
   incomplete bundles keep one shape. → Task 2 test `test_fit_abort_keeps_kv_shape`.
4. **A model on two tiers where one run lacks a suite,** or has an item id the other lacks. Only shared
   suites and shared ids count, and `n` reflects that. → Task 4 test `test_agreement_uses_shared_items_only`.
5. **A `_commit` file with a trailing newline or CRLF from a Windows checkout.** Strip it before the
   40-hex check. → Task 1 test `test_archive_commit_strips_newline`.

### Task 4: `quality_agreement` in week.json

**Files:**
- Modify: `src/bakeoff/runview.py` (`RunView` and `_read_items`)
- Modify: `src/bakeoff/week.py` (`build_week`)
- Modify: `src/bakeoff/schemas/week.v1.json` (top-level `properties`)
- Test: `tests/test_runview.py`, `tests/test_week.py`, `tests/test_rederive.py`

**Interfaces:**
- Produces:
  - `RunView.outputs: dict[str, dict[str, str]]` maps suite key → item id → SHA-256 hex of the item's
    `output` string (the empty string's hash when `output` is null). It's filled where `items` is filled.
    Give it a `field(default_factory=dict)` default placed before `meta`, so existing constructors keep
    working.
  - `quality_agreement(runs: dict[str, tuple[RunView, RunEntry]]) -> list[dict]` in `week.py`, in the
    spec's shape.
  - `build_week` sets `doc["quality_agreement"]` only when the list is non-empty.
- **Rules (from the spec):**
  - group runs by `model_key`, and keep groups covering at least two distinct `entry.tier`, one run per
    tier (its lowest `run_id`);
  - only suites with `split == "public"` and per-item records in every chosen run;
  - over the item ids common to all of them: `same_pass` when every run's pass is equal, and
    `same_output` when every output hash is equal;
  - `runs` sorted;
  - entries sorted by `(weights, quant, runtime)`;
  - suites keyed by suite key, inserted in sorted order.

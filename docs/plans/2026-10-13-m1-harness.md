# M1 Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `bakeoff` Python package. Its CLI (`run`, `judge`, `env`, `verify`) measures quality, speed and fit against any OpenAI-compatible endpoint and writes a hashed run bundle that passes a scrub check.

**Architecture:** A `src/`-layout package. Each measurement pass (quality, speed, fit) is an async function over a shared `EndpointClient`. A background thread samples memory and power locally, and environment capture is an allowlist where each field records its provenance. `runner.execute_run` composes the passes into a bundle; `cli.py` is thin argparse wiring. Suites are data directories (`manifest.toml` + `items.jsonl`) that ship inside the wheel.

**Tech Stack:** Python ≥ 3.11, httpx (the only runtime dependency), the standard library (`tomllib`, `asyncio`, `threading`, `subprocess`), and uv, pytest and ruff for development.

**Spec:** [docs/specs/2026-10-13-m1-harness-design.md](../specs/2026-10-13-m1-harness-design.md). Read it before starting any task.

## Global Constraints

- `requires-python = ">=3.11"`. The only runtime dependency is `httpx`; dev dependencies are `pytest` and `ruff`. There is no pytest-asyncio: async code is tested with `asyncio.run(...)` inside sync tests.
- Commands (`<repo>` is the absolute path to the checkout): `uv run --project <repo> pytest -q`, `uv run --project <repo> ruff check`, `uv run --project <repo> ruff format --check`. Use absolute paths; don't run `cd X && …`.
- Ruff: `line-length = 100`, `target-version = "py311"`, `select = ["E", "F", "I", "UP", "B"]`.
- This repo becomes public. Committed files (including test fixtures and suite content) must not contain internal hostnames, private or LAN IPs, real `host:port` pairs, usernames or local paths. Fixtures use fictional values: hostname `lab-box-7`, username `alice`, documentation IPs only (`192.0.2.x`, `198.51.100.x`) except where a test plants a violation on purpose.
- Bundles never contain: the endpoint URL, `api_key_env`, the hostname, the username, IPs, ports, file paths, environment variable values, GPU serials/UUIDs or MAC addresses.
- Every environment field has the form `{"value": ..., "source": "measured" | "reported" | "operator" | "not_captured"}`.
- Canonical JSON (for every hash): `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")`.
- Outputs from private suites go to `private/` in the bundle, and their item text never appears anywhere in it.
- `runs/` is git-ignored; never commit anything from it.
- A line that plants a scrub violation on purpose (in a test or an example) carries the marker `scrub-ok`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work stays on the `m1-harness` branch, and nothing is pushed without asking.

## Review Focus

1. **Reasoning text inline in `content`.** Ollama and llama.cpp serve some models that emit `<think>…</think>` inline in `content`. The grader must see the answer with the think block removed, and an unterminated `<think>` (cut off by `max_tokens`) leaves empty content. Pinned in Task 8.
2. **Servers that reject `stream_options`** with a 400. The client must retry once without `stream_options`, stop sending it for the rest of the run, and mark the token counts as `estimated`. Pinned in Task 8.
3. **Ollama's implicit `:latest` tag.** The config says `llama3.1` while `/v1/models` lists `llama3.1:latest`. Preflight must accept that and must fail clearly on a real mismatch. Pinned in Task 14.
4. **`base_url` variants.** Given with a trailing slash, without `/v1`, or with `/v1/`, it must normalize to `…/v1`, and the runtime probes must use the root. Pinned in Task 8.
5. **A host with no working `nvidia-smi`** (not installed, or exiting non-zero after a driver mismatch). The run must continue, with the GPU fields and samples set to `not_captured`. Pinned in Tasks 9 and 10.

### Task 2: Bundle writing, verify and scrub scan

**Files:**
- Create: `src/bakeoff/bundle.py`
- Test: `tests/test_bundle.py`

**Interfaces:**
- Consumes: `hashing.canonical_json`, `hashing.sha256_hex`, `hashing.sha256_file`
- Produces:
  - `bundle.slug(label: str) -> str`: lowercase, runs of non-alphanumerics become `-`, stripped of `-`, at most 40 characters.
  - `bundle.run_id(started: datetime, label: str, salt: bytes) -> str`: `f"{started:%Y%m%dT%H%M%SZ}-{slug(label)}-{sha256_hex(salt)[:8]}"`, with `started` in UTC.
  - `bundle.write_bundle(run_dir: Path, meta: dict, files: dict[str, list[dict]]) -> str`:
    - writes each `files` key (a relative path such as `"quality/general.gsm8k.jsonl"`) as JSONL, one `json.dumps(rec, sort_keys=True, ensure_ascii=False)` per line, UTF-8 with a trailing newline;
    - sets `meta["files"] = {relpath: sha256}` and `meta["bundle_sha256"] = sha256_hex(canonical_json(meta minus bundle_sha256))`;
    - writes `bundle.json` with `indent=2, ensure_ascii=False`;
    - returns the bundle hash.
  - `bundle.Finding` (frozen dataclass): `file: str`, `line: int`, `kind: str`, `detail: str`. `kind` is one of:
    - `missing_file`, `hash_mismatch`, `unlisted_file`, `bundle_hash`, `incomplete`;
    - `private_ip`, `host_port`, `home_path`, `username`, `denylist`.
  - `bundle.scan_text(text: str, terms: list[str], username: str | None = None) -> list[tuple[int, str, str]]`: `(line_no, kind, match)` for every scrub kind. The username and denylist terms are matched as whole words, case-insensitively. Terms shorter than 3 characters are ignored.
  - `bundle.verify_bundle(run_dir: Path, username: str | None, denylist: Path | None) -> list[Finding]`. The CLI passes `getpass.getuser()` and `~/.config/bakeoff/denylist` when they exist. `status != "complete"` produces an `incomplete` finding.

The scrub patterns (decided here; the spec names the classes):
- **IPv4:** `10/8`, `172.16/12`, `192.168/16`, `100.64/10`, `169.254/16`, `127/8`.
- **IPv6:** addresses starting with `fc`/`fd` (ULA) or `fe8`–`feb` (link-local) followed by `:`.
- **host:port:** `(?i)\b(?=[a-z0-9.-]*[a-z])[a-z0-9-]+(?:\.[a-z0-9-]+)*:\d{2,5}\b`. This matches `localhost:8000`, but not `gpt-oss:20b` or `12:30`.
- **Home paths:** `/Users/<name>`, `/home/<name>` and `C:\Users\<name>`, where `<name>` is `[A-Za-z0-9._-]+`. A bare `/Users/` in prose doesn't match.

### Task 3: Needle builder and suite loading

**Files:**
- Create: `src/bakeoff/needle.py`, `src/bakeoff/suites.py`, `scripts/lock_suites.py`
- Test: `tests/test_needle.py`, `tests/test_suites.py` (fixture suites under `tests/data/suites/`)

**Interfaces:**
- Consumes: `hashing.canonical_json`, `hashing.sha256_hex`
- Produces:
  - `needle.build_haystack(n_lines: int, seed: int) -> list[str]`: deterministic fictional log lines, in the form `"Record {i:05d}: the {town} depot logged {n} crates of {goods} on day {d}."`, drawn with `random.Random(seed)` from fixed word lists.
  - `needle.needle_messages(n_lines: int, depth: float, seed: int) -> tuple[list[dict], str]`:
    - builds a haystack of `n_lines` lines;
    - inserts `"The access code for the vault is {KEY}."` at index `round(depth * n_lines)`, where `KEY` is `f"{WORD}-{4 digits}"` from the seeded RNG;
    - the user message is the haystack plus `"\n\nWhat is the access code for the vault? Reply with the code only."`;
    - returns `(messages, key)`.
  - `suites.Item(id: str, messages: list[dict], expected: Any)` (frozen dataclass).
  - `suites.Suite` (dataclass): `path`, `track`, `name`, `version: int`, `split: str`, `license: str`, `source: dict`, `grader: str`, `grader_options: dict`, `max_tokens: int`, `system: str`, `items: list[Item]`, `generator: dict | None`, `hash: str`. Also a property `key -> f"{track}/{name}"`.
  - `suites.SuiteError(Exception)`
  - `suites.load_suite(path: Path) -> Suite`. It validates that `split` is in `("public", "private")`, that the grader is non-empty and that `max_tokens > 0`. An item with `prompt` becomes `[{"role": "user", "content": prompt}]`. A non-empty `system` is prepended to every item's messages.
    - **Generated suites:** `generator = {name = "needle", lines = [...], depths = [...], seed = N}` produces one item per (lines × depth). The id is `f"needle-{lines}-{int(depth*100)}"` and `expected` is the key.
    - **Hash:** `sha256_hex(canonical_json({"manifest": <raw manifest dict>, "items": [<raw item dicts>]}))`. For a generated suite, `items` is `[]` and the generator parameters in the manifest carry the identity.
  - `suites.suites_root() -> Path`: `Path(bakeoff.__file__).parent / "suites"` if it exists (installed wheel), else `<repo>/suites`, found by walking up from `__file__`.
  - `suites.resolve_suites(refs: list[str]) -> list[Suite]`. Each ref is an existing directory path or a name under `suites_root()`. A directory without a `manifest.toml` is searched recursively, and suites are returned sorted by `key`.
  - `suites.check_lock(found: list[Suite], lock: dict) -> list[str]`. The lock maps `key` to a `{version: hash}` dict. It returns a problem when a suite's version is in the lock with a different hash ("bump `version`") or when the key or version is missing ("run scripts/lock_suites.py").

### Task 4: Grader registry

**Files:**
- Create: `src/bakeoff/graders.py`
- Test: `tests/test_graders.py`

**Interfaces:**
- Produces:
  - `graders.Grade(passed: bool | None, score: float, reason: str)` (frozen dataclass). `passed=None` means deferred.
  - `graders.register(name: str)`, a decorator that adds to `graders.GRADERS: dict[str, Callable[[str, Any, dict], Grade]]`.
  - `graders.grade(grader: str, output: str, expected: Any, options: dict) -> Grade`. An unknown grader raises `KeyError`.
  - `graders.validate_schema(value: Any, schema: dict, path: str = "$") -> list[str]`: the subset `type` (string, number, integer, boolean, object, array, null), `properties`, `required`, `enum`, `items` and `additionalProperties` (bool).
  - The registered graders:

    | Grader | Rule |
    |---|---|
    | `exact` | `output.strip() == expected` |
    | `numeric` | The last number in the output (commas and `$` stripped, sign and decimals allowed) equals `float(expected)` within `options.get("tolerance", 1e-6)` |
    | `regex` | `re.search(expected, output, re.I if options.get("ignore_case") else 0)` |
    | `json_schema` | Strip one optional `json` code fence, then `json.loads` the whole remainder and validate it; the reason lists the first 3 errors |
    | `needle` | `expected in output` |
    | `grounding` | See below |
    | `judge` | `Grade(None, 0.0, "deferred to bakeoff judge")` |
    | `executable` | Not registered (out of scope) |

  - `grounding` takes `expected = {"must_include": [...], "must_not_include": [...], "answerable": bool}` and a refusal marker `options.get("refusal", "NOT IN CONTEXT")`. Matching is case-insensitive.
    - **Answerable:** passes when every include is present, no exclude is present, and there is no refusal.
    - **Unanswerable:** passes when the refusal marker is present and no exclude is present.

### Task 12: Speed pass

**Files:**
- Create: `src/bakeoff/speed.py`
- Test: `tests/test_speed.py`

**Interfaces:**
- Consumes:

  - `config.SpeedConfig`

  - `sampler.Sampler.mark` (optional)
- Produces:
  - `speed.SHAPES: dict[str, list[dict]]`, with entries `"short"` and `"long"`:
    - `"short"`: `build_haystack(4, seed=1)` plus the instruction `"Write a numbered list of 60 practical tips for keeping these depots organised. Number every tip and keep going until you reach 60."`;
    - `"long"`: `build_haystack(80, seed=2)` plus `"Summarise the records above as a numbered list of at least 40 observations."`.
  - `speed.MAX_TOKENS = 256`
  - `speed.run_speed(client, cfg: SpeedConfig, runtime: str, sampler: Sampler | None = None) -> tuple[list[dict], dict]` (async). For each shape, then each concurrency `c`:
    - first `cfg.warmup` warmup rounds, which aren't recorded;
    - then `cfg.repeats` measured rounds. Each round fires `c` concurrent `chat` calls with `asyncio.gather` and `extra = {"ignore_eos": True}` when the runtime is in `("vllm", "llamacpp")`.

    The sampler is marked `"speed"`, and one `ErrorBudget("speed")` covers the pass.
  - Each request record has exactly these keys: `shape`, `concurrency`, `round`, `prompt_tokens`, `completion_tokens`, `usage_source`, `ttft_s`, `decode_s`, `total_s`, `ignore_eos`, `error`.
  - The summary is `{f"{shape}@{c}": {"ttft_s", "prefill_tps", "decode_tps", "aggregate_tps", "usage_source", "ignore_eos"}}`. Each metric is a `summarize()` dict:
    - `prefill_tps = prompt_tokens / ttft_s`;
    - `decode_tps = (completion_tokens - 1) / (t_last - t_first)`, skipped when `completion_tokens < 2` or the time is zero;
    - `aggregate_tps`: per round, the sum of completion tokens / (the latest `t_last` minus the earliest `t_start`).

    Per-request metrics are pooled over all measured requests in the cell, and `aggregate_tps` over the rounds. `usage_source` is `"estimated"` if any request in the cell was estimated. When a token count is estimated, it uses `chunk_count`.

### Task 13: Fit pass

**Files:**
- Create: `src/bakeoff/fit.py`
- Test: `tests/test_fit.py`

**Interfaces:**
- Consumes:

- Produces:
  - `fit.calibrate(client) -> tuple[float, float] | None` (async). It sends `needle_messages(50, 0.5, 11)` and `needle_messages(200, 0.5, 11)` with `max_tokens=1` and returns `(tokens_per_line, intercept)` from the two `prompt_tokens`. It returns `None` when usage isn't reported.
  - `fit.run_fit(client, cfg: FitConfig, runtime: str, server_context: int | None, sampler: Sampler | None = None) -> tuple[list[dict], dict]` (async).
    - **Limit:** `limit = cfg.max_context or server_context`, and steps above `limit` are recorded as `skipped`. Without calibration, use 25 tokens per line and an intercept of 50, and set `truncation_check` to `"not_captured"`.
    - **Each step:** `lines = floor((step - intercept - 320) / tokens_per_line)` (320 leaves room for the question and 64 output tokens). For each depth in (0.1, 0.5, 0.9), send `needle_messages(lines, depth, seed=step)` with `max_tokens=64`. The sampler is marked `f"fit:{step}"`, and `kv_cache_usage()` is read after the step for vLLM.
    - **Pass rule:** a step passes only when every depth is accepted (no error), has `abs(prompt_tokens - expected) / expected <= 0.05` (when calibrated), and contains the key.
    - **Stop rule:** the pass stops at the first failing step, and later steps get status `not_run`. This is decided here: the spec's "largest passing step" assumes fit is monotone.
    - **Budget:** a 4xx that mentions context length is an expected failure, not a budget error. Only transport errors and 5xx go to `ErrorBudget("fit")`.
  - Each record has exactly these keys: `step`, `depth`, `lines`, `expected_prompt_tokens`, `prompt_tokens`, `accepted`, `within_5pct`, `retrieved`, `ttft_s`, `error`.
  - The summary is `{"max_context_passed": int | None, "server_context": ..., "limit_source": "operator" | "reported" | "none", "truncation_check": "measured" | "not_captured", "steps": {step: {"status": "pass" | "fail" | "skipped" | "not_run", "kv_cache_usage": float | None}}}`.

  - `judge.run_judge(bundle_a: Path, bundle_b: Path, client: EndpointClient, judge_model: str, prices: Prices, max_usd: float, allow_partial: bool, out_root: Path, suite_key: str = "general/open-ended") -> Path` (async). It writes `runs/judge-{hashA[:8]}-vs-{hashB[:8]}/` via `write_bundle`:

      - `estimate_usd`, `cost_usd`;
      - `counts {a, b, tie}`, `win_rate_a` (`a / (a + b)`, or None), `ci95` (Wilson on a out of a+b).

  - `JudgeError` is raised when:

    - the suite hashes differ between the bundles, or don't match the current `suites_root()` suite;

    - the estimate is over `max_usd` and `allow_partial` is False.

    With `allow_partial`, items run in id order until `cost_usd + per_call_worst_case > max_usd`, and `status` is then `"incomplete"` with reason `"budget"`.
